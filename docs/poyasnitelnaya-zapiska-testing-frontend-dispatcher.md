# 3.3.3 Тестирование клиентской части приложения (роль «диспетчер производства»)

Тестирование клиентской части информационной системы ConditerTrans выполнялось для проверки корректности работы пользовательского интерфейса веб-приложения диспетчера производства и основных сценариев поведения пользователя. Проверялась загрузка экранов, работа навигации в шапке приложения, отображение данных, полученных от серверного API, и выполнение действий по обработке заказов.

Клиентская часть тестировалась в браузере (сборка Expo Web: `npm run web`). Пользователь с ролью **Dispatcher** последовательно выполнял действия, соответствующим основным бизнес-процессам диспетчера производства: вход в приложение, просмотр и поиск заказов, принятие решения по заказу, подтверждение готовности к отгрузке, фиксация передачи груза логисту, формирование аналитических отчётов.

**Учётная запись для тестов:** `seed-dispatcher-1@load.test`, пароль `Password1!`.

**Среда:** браузер Google Chrome / Microsoft Edge, разрешение экрана не ниже 1280×720; backend API доступен по адресу из `EXPO_PUBLIC_API_URL`.

### Методика и связь с тестированием серверной части

Клиентские сценарии (таблица 48) выполнялись **после** или **совместно** с проверками API (таблица 47, раздел 3.3.2): каждое действие в интерфейсе сопровождалось контролем HTTP-запроса во вкладке «Сеть» инструментов разработчика браузера (метод, URL, код ответа, тело JSON).

Для модифицирующих операций (п. 10–15) дополнительно проверялось соответствие отображаемого статуса данным в PostgreSQL (раздел 3.3.2).

### Выводы

В таблице 48 приведены основные тестовые сценарии клиентской части для роли **диспетчера производства**. Для каждой проверки указаны действия пользователя, ожидаемый и фактический результат.

Проверка показала, что пользовательский интерфейс:

- корректно отображает данные, полученные с сервера в формате JSON;
- обеспечивает навигацию между экранами «Заказы», «Карточка заказа», «Отчёты», «Профиль»;
- позволяет выполнять полный цикл обработки заказа (подтверждение, отказ, перенос, готовность к отгрузке, передача логисту) через модальные окна без ручного обращения к базе данных;
- формирует аналитические отчёты по отказам и рейтингу продукции за выбранный период.

Полный набор скриншотов тестирования серверной и клиентской частей приложения может быть представлен в приложении к пояснительной записке. В приложение целесообразно включить: экран авторизации, список заказов с поиском и пагинацией, карточку заказа с действиями, модальные окна отказа и готовности к отгрузке, вкладки отчётов, сообщения об ошибках.

В результате тестирования клиентской части установлено, что веб-интерфейс диспетчера производства работает корректно. Пользователь может войти в систему, просмотреть и найти заказы, принять решение по заказу, зафиксировать готовность и отгрузку, сформировать отчёты и завершить сеанс.

Таким образом, функциональное тестирование подтвердило работоспособность разработанного приложения в части роли диспетчера: **серверная часть** корректно взаимодействует с PostgreSQL и возвращает данные клиенту, **клиентская часть** обеспечивает выполнение основных пользовательских сценариев автоматизированного рабочего места диспетчера производства ConditerTrans.
