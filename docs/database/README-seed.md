# Seed и проверки БД

## Порядок запуска (DataGrip / psql)

1. `seed-utils.sql` — опционально (функция `seed_load_uuid` дублируется в каждом скрипте).
2. `seed-companies-5x3.sql` — 15 компаний (5×3 типа) + 5 диспетчеров на производство.
3. `seed-products-100k.sql` — 64 категории + 100 000 продуктов (20 000 на каждое производство).
4. `verify-dispatcher-order-company-scope.sql` — проверка изоляции заказов для диспетчера.

Для больших заказов/грузов: `seed-load-test.sql` (отдельно, после справочников).

## UUID-префиксы

| Префикс | Сущность |
|---------|----------|
| `a001…` | Категории (1–64) |
| `b001…` | Продукты (1–100000) |
| `f001…` | Компании производства (1–5) |
| `f002…` | Компании закупок (1–5) |
| `f003…` | Компании логистики (1–5) |
| `c002…` / `d002…` | Пользователи / сотрудники диспетчеров (не c001/d001 — водители load-test) |

## Диспетчер и компания заказа

На API фильтр уже в `OrderRepository.BuildDispatcherOrdersQuery`: заказ виден только если **все** строки — товары `productionCompanyId` из JWT (`CompanyId` диспетчера). Черновики (`Draft`) исключены.

SQL-проверка повторяет это условие и падает, если есть заказы с товарами разных производителей или «утечка» в видимой выборке.

Тестовые диспетчеры: `seed-dispatcher-1@load.test` … `seed-dispatcher-5@load.test` (пароль как в `seed-load-test`: `Password1!`).
